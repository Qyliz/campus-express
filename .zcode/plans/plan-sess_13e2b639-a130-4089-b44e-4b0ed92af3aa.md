# 前端优化计划（样式复用 / 删除无用样式 / 异步加载）

## 现状问题（已探明）
- **样式重复**：三个 Dashboard（Admin/Customer/Courier）约 140 行样式 ×3 逐字重复；两个布局（AdminLayout/UserWorkspaceLayout）约 80 行 ×2 重复；UsersView 与 AuditsView 弹窗缩略图样式 ×2 重复；认证三页小样式 ×3 重复；分页样式 4 种写法并存（全局 `.pager` / scoped `.pager` / `.pagination`）。
- **无变量收口**：颜色硬编码（`#287dcc`/`#172b3d`/`#e7edf3`/`rgba(34,61,83,…)`）散落各文件；`main.css` 298 行中 85% 是认证页专用的 Element Plus 深色覆盖，职责混杂。
- **无用样式**：需全量审计（此前只抽查过部分文件，未发现明显死样式，但 ProfileView 713 行等未逐行核对）；另 `ProfileView:557` 的 `.avatar-fallback` 与两个布局同名不同义。
- **异步加载为零**：21 条路由全部静态 import（`router/index.ts:101` 注释记录了旧的刻意决策，本次按新要求推翻并更新注释）；`HomeView.vue:3-5` 静态打入 LoginView + 两个 Dashboard；产物为单一 680KB JS + 232KB CSS；`el-image` 未用 lazy；hero 图 2.0MB 未压缩。

已确认：采用**原生 CSS 变量**（不引入 SCSS）；hero 图**尝试压缩**（工具不可用则跳过并说明）。

## 一、样式基建：design tokens + main.css 拆分
新建 `src/assets/styles/`，`main.ts` 按序引入：
- `tokens.css` — `:root` CSS 变量：品牌色（--ce-primary 等）、文字三阶色、边框色、卡片阴影、圆角、布局深色渐变。来源取自现有硬编码色板。
- `main.css` 瘦身为：reset + body + 工具类（`.page-card`/`.muted`/`.mono`/`.pager`），颜色改用变量。
- `auth-theme.css` — 原 main.css 22-281 行的 `.auth-card--backdrop` EP 覆盖整体迁入（原样迁移，色值换变量），**行为不变**。
- `dashboard.css` — 三个 Dashboard 共享样式（见二）。
- `workspace-shell.css` — 两个布局共享样式（见二）。

## 二、样式复用（消重约 400+ 行）
1. **抽公共组件 `src/components/StatCard.vue`**：props = icon/label/value/tone(blue|amber|violet|red|green)，内聚原 `.stat-card` 全部样式。三个 Dashboard 模板中的 4 张统计卡改用它。
2. **`dashboard.css`**：welcome/stats 网格/section-heading/recent-card/dashboard-alert/order-id/表格行 cursor 及 3 个媒体查询合并为一份；选择器统一挂在共享根类 `.dashboard-page`（三个 Dashboard 根类统一改为它，避免通用类名泄漏到全局）。
3. **`workspace-shell.css`**：两布局的 brand/brand-mark/account/avatar/avatar-fallback/account-text 系列合并为一份，挂在共享根类下；删除两份重复。
4. **认证三页**（Login/Register/ForgotPassword）：`.title`/`.submit`/`.links`/`.code-row`/`.mock-code` 等小样式并入 `auth-theme.css`（复用 `.auth-card` 体系）。
5. **admin 弹窗缩略图**：`.thumb`/`.thumb-fallback`/`.dialog-target`/`.dialog-tip` 抽入共享（挂到现有全局工具类文件或 admin 共享段），UsersView/AuditsView 引用。
6. **分页统一**：统一用全局 `.pager`（margin-top 统一为一值）；删除 OrderListView/ExceptionsView 的 `.pagination`、ReviewAppealsView 的 scoped `.pager` 覆盖。
7. **`.avatar-fallback` 同名不同义**：ProfileView 中改名为 `.profile-avatar-fallback`，消除与布局共享样式的歧义。

## 三、删除无用样式
- 写一次性 Node 脚本（不进仓库）：解析全部 22 个 .vue 的 style 选择器与模板/脚本中 class 引用比对，输出疑似死样式清单；对动态 `:class` 绑定的类逐个人工确认后再删。
- 重复样式合并本身即删除大量冗余；审计结果中确认无引用的选择器一并清理。

## 四、异步加载
1. **路由懒加载**：`router/index.ts` 全部页面级组件改 `() => import()`；布局组件保持静态（布局小且必现）。更新 L101-102 注释，写明新决策理由（主 bundle 680KB 过大，按需分包）。
2. **HomeView**：LoginView/CustomerDashboard/CourierDashboard 改 `defineAsyncComponent(() => import(...))`，不再全部打进 home chunk。
3. **vite.config.ts** 增加 `build.rollupOptions.output.manualChunks`：`element-plus` + `@element-plus/icons-vue` 拆 vendor chunk；`vue`/`vue-router`/`pinia` 拆基础 chunk。
4. **图片懒加载**：UsersView/AuditsView/ProfileView 的 `el-image` 加 `lazy` 属性。
5. **hero 图压缩**：找到引用点（HomeView landing 背景图），用 npx 工具（sharp-cli 等）转 WebP 压缩（目标 <300KB），替换引用；失败则保留原图并在总结中说明。
- 保持不动：路由守卫 `await auth.init()`（防闪烁的有意设计）、Element Plus 按需引入体系。

## 五、验证
1. `npm run build`（含 vue-tsc type-check）通过。
2. 对比 dist 产物：确认 JS/CSS 分包效果（主 chunk 显著变小、vendor 独立、页面按路由分包）。
3. 起 dev server 浏览器抽查视觉无回归：登录/注册/首页 landing（无需后端）为主；若后端在运行则加查管理端与用户端 Dashboard、统计卡、弹窗缩略图、分页。

## 执行顺序
基建(tokens+拆分) → Dashboard 消重+StatCard → 布局消重 → 认证页/admin 弹窗/分页收口 → 死样式审计清理 → 路由与组件懒加载 → manualChunks + el-image lazy → hero 图压缩 → 构建+视觉验证。
全程遵循项目现有注释风格，关键决策（推翻路由静态导入）写明注释；不新增运行时依赖。
